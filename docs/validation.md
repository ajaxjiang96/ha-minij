# 验证结果与边界

更新于 2026-10-26。主要运行环境为 HA 2026.10.4、CPython 3.14，
测试区分自动化、真实云端读取、用户安装反馈和完整周期语义。

## 自动化验证

- 基础版本：16 个测试在已核验官方 Python 镜像的 Linux ARM64 容器中退出 0，Ruff 通过。
  镜像及层摘要已验证，只只读挂载源码、合成测试和配置，未挂载账号材料。
- 短信版本：66 个测试通过 GitHub Linux CI，覆盖最低和当前 HA，hassfest/HACS 通过。
- 诊断版本：70 个测试通过 GitHub Linux CI，两个 HA 环境及 hassfest/HACS 均通过；
  对 `9bb6914` 的 Codex 审查无发现。对应 PR 是否合并需查询 GitHub，不能仅凭通过检查推断。

API 测试使用真实本地 HTTP 服务验证请求头、POST JSON、错误分类、敏感响应屏蔽、
非法数据及拒绝重定向。HA 运行时测试仅模拟小吉服务，保留实际流程、协调器、实体和注册表。
覆盖登录显式提交、无自动补发、兑换后读取重试、同账号限制、重复账号、重新配置、
实体稳定、翻译加载、故障恢复、多设备生命周期及诊断白名单。

macOS 的 HA 组合测试在断言完成后仍可能因解释器收尾崩溃而退出 139（一次诊断为 138）。
仅使用 HA 内置 `input_boolean` 的独立基线也复现了 GC / `dictkeys_decref` 收尾问题，
具体原生依赖原因未隔离。不能将断言通过等同于进程成功，干净退出以 Linux CI 为准。
没有添加强制退出或生产绕过来掩盖它。

打包脚本只包含组件运行文件，校验 ZIP 完整性；不含账号文件、原始抓包、APK 或本地工具环境。

## 真实云端与 HA

本地 `analysis/runtime/live-homeassistant.py` 曾使用真实 profile/设备 GET，
完成实际 HA 登录流程、协调器、五个实体和卸载，退出 0。
当时观测为空闲、标准、主洗、童锁关闭、云端授权开启，型号为 `minij.washer.x68`，
软件版本 `1.0253 0 0003 1 0000`。该脚本不是用户生产 HA 的前端验收。

用户生产 HA 截图随后确认五个实体可用，并显示 `device_exception → working`。
所有者反馈新短信流程可用；截图还发现旧翻译缓存，已提供刷新/完整替换翻译文件方法，
并增加 HA 实际翻译加载测试。App 是否保持会话、重启和自然过期尚未完整确认。

## 三份诊断快照

仅记录白名单字段和相对时间，不公开原始文件或其系统元数据。

| 相对导出时间 | 状态 | 程序 | 进程 |
| --- | --- | --- | --- |
| 0 秒 | `resting` / 休息中 | 标准 | 脱水 |
| 约 53 秒 | `working` / 工作中 | 筒自洁 | 主洗 |
| 约 143 秒 | `resting` / 休息中 | 标准 | 主洗 |

均为条目已加载、最近云端刷新成功，在线原始值 `1`，型号和固件一致。
这确认了上报值的变化及空闲进程残留，**未确认正常完成、取消或停止的区别**。
`captured_at` 是导出时间，不是设备事件或最近读取时间。

## 诊断边界

MiniJ 导出白名单缓存，不复制 config-entry 数据、令牌、账号/设备标识、昵称、序列号
或任意嵌套响应；导出不请求网络，云端失败时保留明确标记的缓存。
HA 会添加系统元数据外围，分享前需检查。
未加载条目可以导出空缓存及空协调器状态，不假装有新鲜数据。

## 当前可作出的结论

可以作为有已知限制的监测预览版继续推进，不要求所有者再等待或额外启动洗涤。
不将 `working → resting` 映射为成功完成，不据此提供默认完成通知；
不暴露猜测的剩余时间、具体故障或物理离线语义。
正常使用时再按[观察指南](cycle-validation.md)补证据。

## 首个测试版之后的验收与元数据修复

`v0.1.1b1` 已发布并实际核对附件。所有者确认 HACS 安装后，浏览器读取到
0.1.1b1、原条目、1 台设备、5 个实体及原区域。观察到 HA 已有启动过程完成后
MiniJ 自行恢复，没有短信提示；未另行触发重复重启，也未逐项比对该次启动前后的所有原始 ID。
所有者进一步确认本次 HA 登录后小吉 App 仍能查看设备。这些是一次实际观察，
不能推断所有账号的长期有效期、轮换或自然过期行为。

0.1.1b2 准备修复元数据只在初始化读取的问题。每次成功轮询通过 HA 设备注册表
同步已有设备的名称、型号和固件，注册与更新共用同一字段映射。回归测试使用
合成固件/名称变化和真实 HA 注册表，检查设备/实体标识、自定义名称、区域、
请求数量及重载后的保留。没有更新真实设备固件。最终 CI 以对应 PR 的确切提交为准。
