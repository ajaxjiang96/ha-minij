# MiniJ 自定义卡片

`custom:minij-card` 是专用前端卡片：水滴形洗衣机 SVG 线稿、深浅主题、运行时滚筒动画、
云端剩余时间、随状态变化的主按钮，以及可展开的程序/参数和设备设置。
与 MiniJ `0.4.0b5` 配合使用；这是 0.5 前端候选，不修改洗衣机控制协议。

## 安装前端资源

当前仓库在 HACS 中的类别是 **Integration**，只负责后端集成；添加或更新它不会自动安装卡片。
前端候选通过独立 JavaScript 资源加载，尚未作为 HACS Dashboard 仓库发布。

1. 在本 PR 的 **Checks → Validate → Card** 构建完成后，打开对应 Actions 运行页，
   下载 `minij-card` artifact 并解压，得到 `minij-card.js`。下载 Actions 附件可能需要登录 GitHub。
   开发者也可在仓库运行 `npm ci && npm run build`，使用 `dist/minij-card.js`。
2. 将这个文件复制到 HA 配置目录的 `www/minij-card.js`；没有 `www` 目录就创建它。
3. 启用 HA 用户资料中的**高级模式**。打开 **设置 → 仪表盘 → ⋮ → 资源 → 添加资源**，
   URL 填 `/local/minij-card.js?v=0.5-dev1`，类型选 **JavaScript 模块**。
   若使用 YAML 模式仪表盘，在其 `resources` 配置中登记同一 URL 和 `type: module`。
4. 刷新浏览器，编辑仪表盘并添加 **MiniJ** 卡片。在可视化编辑器中选择洗衣机的**状态**实体，
   不要选择设备上报程序或阶段。卡片只列出 MiniJ 的枚举状态传感器。
5. 按需要填写名称和副标题，并选择是否显示滚筒动画、剩余时间和设备设置，然后保存。
   更新 JS 文件后同时更改资源 URL 中的版本查询值并刷新，避免旧浏览器缓存。

不需要更改 MiniJ manifest 版本或重启后端。卡片读取当前用户可访问的 HA 实体注册表，
按所选设备的稳定唯一键发现实体；改名和区域前缀不影响匹配，也不会把另一台设备的控制混入。
手动禁用的实体不展示；程序参数缺失或不可用时不提供对应可写值。

## 卡片编辑器与 YAML

正常配置只需要在可视化编辑器选择一个状态实体。也可以使用
[examples/dashboard.yaml](../examples/dashboard.yaml) 的最小 YAML：

```yaml
type: custom:minij-card
entity: sensor.replace_with_your_minij_status
animation: true
show_remaining: true
show_settings: true
```

`name` 可覆盖卡片标题，`subtitle` 可覆盖副标题；未设置时使用设备名称和区域（HA 提供时）。
配置卡片使用用户自己的实体标识，公开分享前请替换为占位值。
卡片界面跟随 HA 语言，提供简体中文和英文；厂商提供的程序/参数名称及选项保持设备原文。

## 显示与操作

- **主按钮**：待机为唤醒，已唤醒为启动待选程序，运行中为暂停，暂停后为继续。
  状态未知、实体不可用或缺少对应按钮时不提供操作；停止／关机仍使用集成的独立按钮。
- **程序与参数**：点击程序行、设置图标或底部入口展开。程序选择是本地待启动草稿，
  参数修改会立即发送设置请求。下拉框使用当前实体提供的允许值，不硬编码选项，也不自动写入默认值。
- 启动、停止／关机和筒清洁需要确认；确认期间设备或待启动程序变化时不发送旧操作。
  主按钮切换不会自动启动、唤醒或重试。每次点击调用一次已有 HA 动作。
- 请求进行时锁定可写控件；本地程序草稿显示“待启动程序已选定”，其他成功响应只显示“请求已接受”；等新的实体状态报告目标值后，
  才显示“设备已上报目标状态”。这不是证明该请求造成了状态变化。
  失败或结果不确定时提示查看机器和 App，不乐观修改读数、不自动重试。
- 工作时将集成的剩余分钟格式化为 `HH:mm`；暂停、待机或值未知时显示 `—`，不运行本地倒计时。
  空闲时不把保留的阶段当成当前洗涤阶段。没有进度百分比或预计完成时间。
- 滚筒动画只在已报告工作状态时运行，遵循系统“减少动态效果”设置；没有假动画模拟真实洗涤进度。
- **HA 卡片编辑预览中的设备写入被禁用**。预览仍显示真实实体，保存到仪表盘后才提供实际控制。
  下方提示会说明当前是否为编辑预览。
- 完成/故障手机提醒仍由[通知蓝图](automations.md)配置；卡片安装不会自动创建自动化。

## 本地交互演示

`frontend/demo.html` 与 `frontend/tests/fixtures.js` 是合成状态演示，使用构建后的卡片。
构建后可在只含这些公开文件的本地静态目录中打开；支持模拟工作、暂停、待机、唤醒与不可用状态。
演示服务不会访问小吉或 HA，也不构成真实设备验收。

实现使用 [HA 自定义卡片](https://contributors.home-assistant.io/frontend/custom-ui/card/)
和[可视化编辑器](https://contributors.home-assistant.io/frontend/custom-ui/card-editor/)机制。
真实 HA 的资源加载、编辑器及当前实体映射仍需在候选安装后验收；浏览器演示、DOM 回归和现场设备效果分开记录。
