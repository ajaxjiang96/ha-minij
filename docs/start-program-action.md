# 一次调用启动程序并提交参数

当前源码新增实验动作 `minij.start_program`，尚未发布。适用于 HA 脚本、自动化和自行调用 HA 动作的 AI Agent。
它将程序与参数作为一次调用输入，在同一设备锁内读取最新选项、校验并发送一条启动请求，
无需先修改多个下拉框，也不会读取或覆盖卡片中的本地草稿。

## 输入

| 字段 | 含义 |
| --- | --- |
| `entity_id` | 一台洗衣机的“启动待选程序（实验）”按钮实体 ID。使用 HA 分配的实际 ID，支持改名；不接受列表、`all`、设备或区域批量目标 |
| `program` | 设备提供的完整程序名称，例如“标准”或“日常洗”；不能用别的型号名称代替 |
| `parameters` | 可选的对象：参数 `code` → 该程序的选项名称。选项名称和数字映射以当前设备为准 |

动作界面的按钮选择器会列出 MiniJ 按钮，请明确选择“启动待选程序（实验）”，选择其他按钮会报错且不操作机器。
无效、未加载、无权限或不可用的目标不会启动。HA 用户仍需拥有该实体的控制权限。

**未提供的参数使用最新云端元数据当前值，可能沿用上次设置。** 要避免沿用烘干设置，必须明确传入
设备提供的“无烘干”选项，不能只省略 `dryingCompoundOption`。不接受整数或布尔值来猜测协议枚举。
参数 code 和选项名称可从对应程序的 HA 参数实体／脱敏诊断摘要核对；不同程序的选项不一定相同。

## HA 动作示例

在“开发者工具 → 动作”中选择 `minij.start_program`，或在脚本中使用：

```yaml
action: minij.start_program
data:
  entity_id: button.test_washer_start_program
  program: 标准
  parameters:
    dryingCompoundOption: 无烘干
```

上述实体 ID 为合成示例，请替换为自己的按钮。程序与选项也必须是自己的机器实际提供的值。
要启动洗烘，将烘干选项改为该程序提供的“即穿”等名称；只烘干则显式选择设备提供的单烘干程序。
本动作没有硬编码“只洗／洗烘／单烘干”预设，不替用户推断其他相关参数。

如需请求响应，在脚本动作中添加：

```yaml
response_variable: minij_start_result
```

响应按按钮实体 ID 分组，例如：

```yaml
button.test_washer_start_program:
  status: accepted
  program: 标准
```

`accepted` 仅表示云端接受请求，不能解释为机器已开始、正常完成或默认值保持不变。
不请求响应时，也可作为普通 HA 动作使用。

## 自动化与 Agent

- 每次调用明确提供目标、程序和希望覆盖的参数；不要依赖另一个调用者的下拉框草稿。
- 同一设备的启动动作、卡片选择与运行中调参使用同一把锁；并发调用各自的参数不会混用。
  两个有效启动请求仍会顺序发送，不会自动合并或去重，请在自动化／Agent 端避免重复发起。
- 不自动唤醒、不重试、不乐观改写设备状态。机器是否接受当前状态下的启动，由服务端和设备决定。
- 启动可能实际运行机器，请由用户确认机器已准备好。超时或结果不确定时，先核对 App 与机器，避免重复启动。
- Agent 需通过自己的 HA 工具或 API 调用此动作；本项目不提供独立 Agent SDK。
  直接调用小吉云端的客户端仍需自行采用相应协议，安装本集成不会自动修改其实现。

## 验证范围

自动化回归覆盖零值、设备动态枚举、缺省参数、UI 草稿隔离、并发、权限、卸载与异常不重试。
使用合成数据，不操作真实洗衣机。U10 Pro 的实际参数组合效果，以及是否改写云端保存默认值仍待确认。
