## 后续确认：休息状态与独立完成消息

2026-10-26 所有者反馈：本次程序结束后 App 显示“休息中”，另有前一个程序完成通知。
随后对官方网页已经使用的接口进行一次真实查询：

- 设备消息页从主 bundle 导出 `Ba as R`，设备通知页将 `R` 导入为 `c`。
- `c({type: "DEVICE_NOTIFICATION", deviceId})` 对应
  `POST /api/notificationCenter/findByPage`，使用已确认的原始 token 请求头。
- HTTP 200、success=true；响应包含分页元数据和 `content`，本次全部在默认返回页内。
- 最新消息标题“洗衣完成”，正文去除设备名称后为“已完成婴童程序”；
  历史“清洁完成”正文对应筒自洁，“故障提醒”则独立存在。
- `code` 本次为 null；不能虚构稳定的业务事件码。当前候选按目标型号与已确认的精确标题映射。
- “清洁提醒”正文也含“完成若干次任务”，必须保持未识别，不以正文关键词分类。
- 每条有字符串 `id`、`deviceId`、`type`、`pushTime`。时间仅按同一厂商格式比较先后，
  未单独证实时区，不作为 HA 事件时间或机器精确结束时间公开。

主 bundle 的源码偏移：`findByPage` 定义约 33756 字符附近，导出表 `Ba as R`；
设备通知页调用约 1780 字符附近。偏移是已保存 UTF-8 文本的字符位置，原 bundle 哈希见
[网页协议](web-protocol.md)。这是公开客户端的只读查询 POST，不是短信或设备命令。
`singleNotificationHasBeenRead`、`allRead`、`clearNotification` 等独立接口均未调用。
原始历史和账号/设备字段仅保留在忽略的私有文件，公开文档不附原响应。

## 后续确认：暂停上报与操作路径

2026-10-27 所有者确认 App 已工作并有倒计时；同轮只读云端为 `working / 工作中`、
筒自洁、主洗、剩余100分钟。稍后 App 实际显示01:39。所有者随后自行暂停，
App 明确显示“已暂停”，同轮云端为 `paused / 已暂停`，剩余100，App显示01:40。
这些是不同读取时刻的快照，没有据此推断时间冻结规则或补算周期进度；
时间实体继续遵循既有只在 working 输出的规则，原始暂停剩余值保留诊断。

暂停状态翻译有本次真实证据，新增已知枚举 `paused`。运行程序专用读取在暂停时返回
筒自洁程序对象，其 `id` 与 App 离线暂停/继续请求中的程序 ID 一致；不能用待启动草稿代替。

完整控制请求和离线取证过程见[本地控制指南](local-controls-0.4.md)；
请求已生成不等于 HA 新按钮已经完成实机效果验收。
