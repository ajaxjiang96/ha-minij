更新于 2026-10-27。提示音已完成一次真实关闭并恢复开启的验证，所有者听到
“已设置静音”和“静音解除”。0.4.0b1 继续是未发布候选；本次设备证据与代码回归分开记录。

## 已有证据

本机真实更多设置表 `fucntionSettingItemList` 明确列出 `code=promptTone`、
名称“提示音”、`switchStatus=true`；`value`、`linkUrl` 为 null。
与仅见于通用原生代码的入口不同，这是本机服务端返回的设置项，
但它仍不能证明写入会使机器提示音变化。

公开网页更多设置页与中央 API 模块的静态追踪：

- `index-ddfe736f.js` 字符偏移约 6981：读取参数仅 `deviceId`。
- 约 7040：开关处理器构造 `deviceId/basicFunction/onOff/value`；
  约 9150 的开关回调只传设置项与布尔值，第三参 undefined，JSON 序列化省略 value。
- 约 2186：以 `switchStatus` 为开关状态，null 时使用非开关展示。
- `index-ce2bc1d3.js` 约 32572：写入 `device/switchBasicFunction`；
  约 34031：读取 `device/v3/getDeviceMoreSetting`。
- 页面虽然读取路由桶代码，但未把它加入上述请求。不能复制童锁的空桶代码，
  也不能擅自发送 `value:null`。
- 页面收到云端成功后更改本地值，没有回读；本集成候选额外读取真实设置表确认。

合成请求示例：

```json
{"deviceId":"synthetic-washer","basicFunction":"promptTone","onOff":false}
```

GET 的 deviceId 通过 URL 查询编码；认证会话头沿用现有客户端。
解析只认唯一的 `promptTone` 和严格布尔 `switchStatus`，缺项为未知，
整数、字符串、重复项和损坏响应均不当作关闭或可写能力。

## HA 中的候选行为

新增“提示音（实验）”开关，默认禁用。未启用时不新增设置轮询，安装、
加载和启用本身均不发送设备指令。原七个活动监测实体及 ID 保留；童锁候选继续禁用待验。
启用提示音后，每 60 秒独立读取设置；读取失败仅影响这个开关，不隐藏原状态传感器。
采用失败退避和 Retry-After，认证拒绝进入同账号重新认证。

当前写入范围严格限制：`minij.washer.x68`、已观察 Wi-Fi/设备固件、单桶、
云端控制授权开启、明确 `waiting`、设置表提供严格布尔状态。
`waiting` 的选择来自所有者描述“按电源后唤醒、菜单亮起、可以选程序”，
本次真实往返在 waiting 下成功；**不是已验证提示音只能在该状态设置**，
不将此结果扩展到工作中、待机或其他固件。

每次动作先重读设备及设置，校验后只发一次。目标已一致则不写。
同一个开关串行处理，不自动重发、不重定向、不乐观改状态；回读一致才正常返回。
为容纳本次观察到的异步更新，提示音最多回读三次，后两次各等待 2 秒；
只重读，不重发写请求，卸载、不可用或状态未知时停止等待。童锁仍保持原单次回读。
云端接受但未确认、超时、限流、认证拒绝都有中文错误说明；结果不确定时先看 App/机器。
卸载期间不再发送后续写入。真实声音变化由所有者确认；生产 HA 的新开关界面仍待验收。

## 真实往返验收

在合并提交 `fbec2c4e786d1f9944aa8cb5012fb2dbe6666dc8` 上，所有者明确授权
未运行、菜单亮起时切换提示音并恢复原值。首次前置检查为 resting，零写入；
所有者再次唤醒并确认后，读到 waiting、原值 true，发送关闭一次。

即时回读仍 true，独立读取随后变为 false；短暂停留后发送开启一次，
独立回读 true，恢复原值。两条请求均获云端接受，没有重发，卸载成功、进程退出 0。
所有者现场听到“已设置静音”“静音解除”，并确认声音有区别且已恢复。
没有启动洗涤、修改程序/授权/固件，也没有执行童锁命令。

旧版 HA 动作因即时读到旧值返回 `control_not_confirmed`，随后独立读取才确认成功。
因此本次同时证明设备实际往返，并暴露确认窗口过短的问题；不能写成旧 HA 动作已正常返回。
新增的最多三次有限回读由合成 HA 回归验证，本轮未为了验证修复再次操作真实机器。

后续保持原值，无需为测试额外运行洗涤。其他运行状态/固件和生产 HA 安装界面另列待验。
