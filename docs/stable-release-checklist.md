# 首个稳定版验收清单

稳定版目标限定为：V6-XNB、已测试固件、云端账号登录和五个原始状态监测实体。
暂不承诺完成通知、剩余时间、物理离线判断或设备控制。
未暴露的能力不需要为了发布额外运行洗涤来验证。

## 已获得的证据

| 项目 | 证据类型 | 结论与边界 |
| --- | --- | --- |
| 账号与设备读取 | 真实云端、真实 HA | V6-XNB 五个实体已使用 |
| 手机验证码登录 | 所有者反馈 | 当前账号流程可用，不能推广为所有挑战都支持 |
| HACS 安装 | 所有者反馈、HA 页面 | 已安装 0.1.1b1；没有把“源码测试”算作实际安装 |
| 发布附件 | 实际下载核验 | 0.1.1b1 ZIP 摘要正确，14 个文件与标签一致 |
| HA 启动恢复 | 实际浏览器观察 | 看到已有启动过程完成，MiniJ 自动恢复，无需短信；未另行触发重复重启 |
| 手机 App 会话 | 所有者反馈 | 本次 HA 短信登录后仍能查看设备，不证明全部会话轮换规则 |
| 条目与显示设置 | 实际 HA 页面 | 1 台设备、5 个实体及原区域仍在；未对该次启动前后的全部原始 ID 逐项比对 |
| 身份和设置稳定 | 真实 HA 运行时＋合成 API | 同账号认证、恢复、设备移除/返回、云端元数据变化时检查身份；元数据测试还检查自定义名称和区域 |
| 状态边界 | 三份脱敏快照 | 空闲→运行→空闲已观察，正常完成原因未确认，空闲进程可残留 |

## 稳定版前的下一轮验收

1. 在新测试版中验证 HACS 升级：保存原条目，检查五个实体 ID、名称、区域和现有自动化引用，
   不通过删除/重建生产条目来制造干净安装。
2. 有真实认证失败或所有者方便时，确认同账号重新认证后的恢复；不故意撤销可用会话，
   不要求反复发短信。自动化测试已覆盖错误账号拒绝，但不能冒充真实重新认证验收。
3. 持续正常使用，记录自然故障和恢复；发现回归就修复，再决定测试版是否可以转稳定版。
4. 尽可能让另一位所有者按中文 README 独立安装。当前只有一台 V6-XNB 的证据，
   尚不能声称多用户、多型号或所有固件已验证。
5. 针对确切发布提交检查完整 CI、版本、中文说明、支持政策和公开文件隐私。

## 可继续开发，但不能当作已证实

有效期、刷新接口、业务过期码、冷却规则和所有挑战仍未知。
已知 HTTP 401/403 会触发重新认证，未知业务错误不猜测成过期。
新增设备固件/名称同步由合成数据回归验证，不代表安装过真实固件更新。

实际发布需另外执行标签发布流程。当前流程只发布 beta；首个稳定版前需明确扩展
稳定发布支持，并审查该发布范围。版本和发布时间不能仅由清单勾选自动决定。
