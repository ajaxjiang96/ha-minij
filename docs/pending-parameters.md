# 待启动参数与运行中设置

本文对应当前源码功能，尚未发布。已有普通启动及单参数设置的实机结果，不等于本次批量启动已验收。

## 使用

1. 选择“待启动程序”，等待该程序参数加载。
2. 选择“待启动·…”参数，例如“无烘干”。这些选择只保存在 HA 内存，不立即写入设备。
3. 机器准备好后，显式点击“启动待选程序（实验）”。卡片确认框列出当前参数。
4. 启动前重新读取程序元数据，按最新参数 ID、选项映射一次提交。包含值 `0`，不会因其为假值而省略。
5. 如需修改正在运行的程序，使用“运行中·…”实体。它只在云端报告运行／暂停且能读取实际运行程序时提供，
   不使用待启动程序。选项由设备决定；服务端可能拒绝某个阶段的修改。

切换程序清空旧程序的参数草稿；重载集成或重启 HA 也会清空。未显式选择的值使用云端元数据当前值。
显式选择的选项按名称保留，后台刷新不会覆盖；其最新协议数字和参数 ID 在提交时重新解析。
选项删除、默认值变化、排队期间草稿变化或程序变化会要求重新核对，不发送旧请求。
没有可解析的当前值时先选择有效选项；不凭空补出默认值。

既有参数实体的唯一标识保留，但含义变为待启动草稿；依赖旧参数即时写入的自动化需改用“运行中·…”实体。
运行中实体在首次读取到对应参数后创建，空闲时不可用。用户自定义名称会保留，请按需调整以区分两组设置。
当前源码卡片需同步更新后端；旧后端下草稿与启动入口禁用，避免把即时写入误称为草稿。

## 请求与诊断

启动只发送一条 `activate`，每项为字符串字段 `userDeviceModeStatsId`、`code`、`value`。
暂停／继续保留空列表，程序 ID 来自实际运行程序。没有自动唤醒、自动重发或乐观状态更新。
请求成功仅表示云端接受；实际状态仍等待后续轮询，不能因回报延迟重复点击。

诊断包含 `pending_parameters`（选项名称）、`draft_revision`、`running_parameters`（云端值），
以及启动台账的 `parameters`（code/value）。不导出程序或参数 ID。
草稿、运行中回报与台账均是不同证据；台账 `accepted` 不能证明机器按组合执行。
