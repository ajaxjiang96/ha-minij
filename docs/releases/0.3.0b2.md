# 小吉 MiniJ 0.3.0b2 · 官方完成消息候选

候选版本，实际发布以 GitHub Releases 为准。继承 b1 的剩余分钟数，
新增读取官方设备通知的事件实体。V6-XNB 为七个实体，原六个标识保持。

## 完成依据

所有者观察到本次婴童程序结束后 App 回到“休息中”，并收到完成通知。
随后真实只读消息接口返回“洗衣完成／已完成婴童程序”；历史还包括“清洁完成”和“故障提醒”。
这些明确消息支持完成语义，不再依赖 `working → resting` 或剩余时间 `0`。

新“设备通知”事件实体提供：`wash_completed`、`cleaning_completed`、`fault_reported`。
按本次确认的精确标题匹配；未知标题保留为未识别，不搜索正文里的“完成”字样，
因此“清洁提醒／已经完成若干次任务”不会被误认为一次完成。
不将消息正文、昵称、原始消息/设备 ID 或链接放入事件属性。

## 读取与恢复

每台受支持设备独立每 60 秒读取一次消息列表，额外于共享状态请求；
关闭该事件实体即可停止其通知轮询。读取用 POST 查询，不调用标记已读、清空或其他写接口。
通知读取失败独立退避，原状态传感器继续工作；认证拒绝仍进入同账号重新认证。

首次加载、重载及故障/绑定观察间隔恢复后的第一份成功列表只建立基线，不发送历史事件。
后续按消息 ID 去重并用厂商时间水位排除更旧回填。相同秒数的不同新 ID 可分别触发。
事件实体时间表示 HA 处理时间，不冒充机器结束的精确时间。

这是保守的轮询语义：HA 停机、重载、故障窗口内的消息不补报，旧时间迟到消息可被忽略；
默认返回页之外的消息可能漏掉。不保证恰好一次送达或一个物理周期只有一条厂商消息。
首次基线后相同消息 ID 在该运行期内最多处理一次；重启不会把已有消息重新通知。

## 使用与验收

候选实际发布后备份并通过 HACS 测试版下载、重启，保留条目和实体。
新事件最初为未知或显示恢复的旧事件时间，均不表示此刻刚完成。
启用通知时使用 HA 的 `event.received`（事件收到）触发器及本仓库完成示例，
不使用泛化“任何状态变化”来捕捉恢复后的旧时间。

本次真实消息读取及临时 HA 基线与合成新事件测试分开记录。
没有在用户生产 HA 安装候选、创建通知或触发额外洗涤。
正常使用下一次产生新完成消息时，再核对实际通知交付。
暂停/取消字段、特殊时间值、其他阶段/固件、具体故障码及物理离线仍需对照，
不提供预计结束时间或设备控制。
