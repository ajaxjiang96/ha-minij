# 小吉 MiniJ 0.2.0b1 · 可靠监测候选

这是 0.2 阶段的测试候选，尚未发布；实际可下载版本以 GitHub Releases 为准。
限定支持已验证的 V6-XNB，最低 HA 2026.10.4，沿用五个只读实体和原有标识。

## 变化

- 状态显示支持中英文：`resting` 为空闲、`working` 为运行中，
  `device_exception` 为“设备上报异常”，不猜测具体故障。
  HA 内部状态及自动化使用的原始别名不变，未来未知别名原样保留。
- 程序和进程新增“设备上报运行中”属性：工作为 true、空闲为 false，
  其他/缺少状态为 null。程序/进程原值仍保留；false 表示云端上报空闲，
  不能当作正常完成，空闲的程序/进程可能是残留值。
- 连续云读取失败按 60、120、240、480、900 秒退避，之后最多每 900 秒一次；
  成功后恢复每 60 秒读取。限流至少等待 300 秒，并尊重有效 `Retry-After` 中的更长时间。
  这控制自动轮询；用户手动刷新仍可提前发起请求，不会自动登录或发送短信。
- 缓存诊断新增 `last_successful_cloud_refresh`，记录本次 HA 运行中最近一次成功读取云端的 UTC 时间。
  失败时保留，重载后重新建立；它不是设备数据生成时间，也不能证明设备物理在线。
- 短信页面更新为已知 App 共存观察，继续保留其他账号/轮换行为未知的说明。

## 安装与验收

备份 HA，在 HACS 开启测试版并选择**实际已发布**的本版本，完整下载后重启。
不删除已有条目；核对原实体 ID、自定义名称、区域及自动化引用。
检查空闲/运行的显示、原始状态别名及程序/进程上下文；无需额外启动洗涤。

安装、持续使用和自然重新认证的验收见 [0.2 验收记录](../monitoring-acceptance.md)。
代码测试不能替代至少 14 天观察或第二位所有者独立安装；这些仍待完成，
候选不代表完整 M1 已验收。合并不等于发布，本文件不保证版本已可下载。

不提供完成通知、剩余时间、物理离线判断或设备控制。HACS 更新图标来源的问题
与设备本地图标分开处理，当前安装的本地自定义不等于上游已修复。
