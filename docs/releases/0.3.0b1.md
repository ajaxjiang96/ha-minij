# 小吉 MiniJ 0.3.0b1 · 运行时间与异常监测候选

开发候选，实际发布以 GitHub Releases 为准。本候选完成 0.3 已取得证据的一层，
不表示完整周期、完成通知、暂停/取消及物理离线均已验收。

## 新增

- V6-XNB 增加“设备上报剩余时间”实体，单位分钟；原五个实体及标识保持。
  真实运行“婴童／主洗”时，云端剩余 `57` 已与所有者 App 的 `00:57` 对照。
- 只有型号匹配且云端明确 `working` 才显示有效的非负整数；空闲、异常、
  其他/缺失状态或无效值为未知。读取失败或解绑为不可用，不使用空闲残留值。
- 不本地递减、不用剩余 `0` 宣告完成，不把未知暂停/取消状态推断为运行。
  暂停是否可能仍上报 `working` 尚待对照，当前值始终是云端估计。
- 白名单缓存诊断补充进程别名、剩余/总时间原值和存在时的故障码，
  不新增请求，也不推断总时间单位、具体故障或在线标志含义。
- 提供用户自行启用的“上报进入异常状态”自动化示例，
  忽略首次加载、未知/不可用恢复和同状态重复上报；消息不判断具体故障或物理断网。

## 验收与升级

候选发布后备份 HA，在 HACS 选择实际发布的测试版并重启，保留已有条目。
V6-XNB 应有六个实体；确认原五个实体 ID、名称、区域及自动化引用保持。
日常运行时核对新增分钟数与 App HH:mm，空闲时应为未知。
无需额外洗涤、重复登录或操作设备；本次没有在用户生产 HA 安装候选或启用通知。

正常完成、暂停/取消、其他阶段/烘干及特殊时间值仍未完整对照。
不提供完成事件/通知、预计结束时间、物理离线判断或设备控制。
详见[协议证据与缺口](../cycle-protocol.md)和[日常观察指南](../cycle-validation.md)。
