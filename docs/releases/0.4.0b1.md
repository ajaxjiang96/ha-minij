# 小吉 MiniJ 0.4.0b1 · 实验童锁控制候选

开发候选，实际发布以 GitHub Releases 为准。尚未执行真实设备写入验证，
不宣称童锁控制已获真实验收，也不支持启停、暂停、程序选择或其他参数控制。

## 新增

在原七个监测/通知实体之外，为 V6-XNB 注册默认禁用的“童锁控制（实验）”。
已有实体 ID、区域、自定义名称和监测功能保持。安装、加载、启用实体不发送控制指令。

专用请求来自 App 原生 `ChildLockSetup` 路径：认证 POST、固定功能 `childLock`、
布尔 `onOff`、单桶代码为空字符串。没有照搬 MIoT 的编号或枚举。

本候选要求已观察固件、明确空闲、云端授权开启和已知童锁状态。
每次显式动作先读最新状态，单设备串行、目标一致不重写；只发一次、不重试。
云端接受后读回一致才返回成功；未知结果或未确认均明确报错，不乐观显示状态。

默认禁用实体需要所有者手动启用。具体范围、错误处理和真实验证方案见
[实验童锁控制](../child-lock-control.md)。真实写入仍需要另行约定一次开启及恢复原关闭。

## 验证范围

协议字节/反汇编、公开网页结构、只读设置表与合成 HTTP/HA 回归分开记录。
临时 HA 的真实只读烟测中控制实体保持禁用，写方法由 Mock 阻断；
这只能证明加载不会发指令，不能当作真实童锁写入成功。

发布前检查确切提交的完整 CI、hassfest、HACS、安装包与审查。
未验证的其他固件、工作中/烘干状态、桶配置与设备型号不自动放开。
