# 小吉 MiniJ 0.4.0b1 · 提示音实验控制测试版

本测试版在原七个监测/通知实体之外，增加默认禁用的“提示音（实验）”。
V6-XNB 已完成一次真实关闭并恢复开启，所有者听到“已设置静音”和“静音解除”，
云端设置表也确认 true → false → true。支持范围限于已观察型号、固件和状态，
不支持启停、暂停或程序参数控制；童锁仍待验证。

实际可下载版本以 GitHub Releases 为准；合并不会自动发布。

## 提示音控制

手动启用提示音实体后，每 60 秒独立读取设置；未启用时无新增设置轮询。
安装、加载、重启及启用实体本身均不发送命令，原七个活动实体、ID、自定义名称和区域保留。
设置接口故障只影响提示音实体，不隐藏原状态传感器。

每次显式操作先重读设备和设置。仅允许 `minij.washer.x68`、Wi-Fi `1.0253`、
设备固件 `0 0003 1 0000`、单桶、云端授权开启、明确 `waiting` 且提示音状态已知时操作。
这些是测试版范围，不代表其他状态或固件一定不能使用。

动作串行、目标一致不写，只发送一次请求。为容纳本次真实上报延迟，
提示音最多读取三次确认，后两次各等待 2 秒；只重读、不重发，不乐观显示成功。
卸载、读取失败或状态未知时停止；认证拒绝、限流、不确定结果及未确认均有中文提示。
遇到不确定结果先看机器/App，不反复点击。

## 状态展示与童锁边界

`resting` 显示“待机”，`waiting` 显示“已唤醒，待选择程序”；原始自动化状态值不变。
未运行时上报的程序/进程仍可能是残留值。

“童锁控制（实验）”仍默认禁用，尚未验证成功，请保持禁用。
面板童锁已由所有者确认存在，但运行条件和云端指令效果待下次正常洗涤研究。
不因 App 无入口否定硬件能力，也不把通用上报字段当作可写证明。

## 更新与验收

先备份 HA，在 HACS 显示测试版本并选择此版本下载、重启。
在设置 → 设备与服务 → 实体中显示禁用实体，仅手动启用“提示音（实验）”。
确认原七个实体、区域、自定义名称及自动化引用保留，新开关能读取当前值。
无须额外洗涤；首次现场切换已完成，生产 HA 新开关界面仍需所有者验收。
不要把本集成更新与洗衣机固件更新混淆。

完整回归 203 项断言，最低/当前 HA 的 Linux CI、hassfest 和 HACS 检查通过。
macOS 本地测试断言后退出 139 的已知现象仍独立记录。
真实往返发生在有限回读修复之前：旧 HA 动作即时读取落后而报告未确认，
独立稍后读取和机器声音确认成功；修复由合成回归验证，没有为修复额外操作机器。
不将自动化测试、云端 ACK、真实回读和机器观察混为一谈。
