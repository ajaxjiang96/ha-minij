# 小吉 Home Assistant 完整集成路线图

更新于 2026-10-27。稳定渠道为早期监测版 `v0.1.1`，
本轮发布目标为 [`v0.5.0b1`](https://github.com/ajaxjiang96/ha-minij/releases/tag/v0.5.0b1)，此前最新控制测试版为 `v0.4.0b5`。
当前推进 **0.5：自动化与日常体验**；版本范围是规划，不是发布日期或全型号支持承诺。

## 已交付的能力

| 阶段 | 已实现 | 证据边界 |
| --- | --- | --- |
| 0.1：独立接入 | HACS/手动安装、短信/令牌登录、重新认证、状态实体、脱敏诊断、中文文档、CI/发布包 | 所有者真实登录、HA 重启恢复及手机 App 会话保留；不宣称已知长期令牌有效期 |
| 0.2：可靠监测 | 状态翻译和未知值保留、空闲上下文、失败退避、成功读取时间、设备信息同步 | 所有者本机验收；持续使用、真实认证过期与独立用户安装另行收集 |
| 0.3：周期与事件 | 工作时剩余分钟、官方洗衣/清洁完成和故障消息事件、去重、启动/恢复基线、自动化示例 | 分钟数有 App/API 对照；不从回待机推断完成，不承诺恰好一次送达或停机补报 |
| 0.4：程序与控制 | 动态程序/参数、唤醒、启动、暂停、继续、停止／关机、提示音、童锁与智能清洁设置 | V6-XNB 本轮控制已有所有者观察或云端回读；童锁面板效果与所有参数组合未全部确认 |

当前唯一实际验证型号为 V6-XNB（`minij.washer.x68`），Wi-Fi `1.0253`、
设备固件 `0 0003 1 0000`。它通过小吉 App 接入，不把 MIoT `v17` 的枚举或写权限套到本机。
协议、代码回归和现场表现分别见[周期证据](cycle-protocol.md)、
[控制指南](local-controls-0.4.md)和[验收记录](validation.md)。

0.4 本轮用户授权采用本地集中验收，随后公开发布 b5：默认启用已提供的控制，
移除人为型号/固件/运行状态门槛，保留绑定、有效元数据、活动生命周期和必要程序身份检查。
控制单次发送、不自动重试或唤醒，不乐观伪造执行结果；设备与云端仍决定是否接受操作。

## 0.5：自动化与日常体验

第一批交付是通知蓝图与独立前端卡片，可在 `0.4.0b5` 使用；不修改控制协议或后端运行包版本。
源码、PR 合并、公开发版和用户实际验收分别记录。所有者已安装前端候选并确认显示效果正常；通知渠道和新卡片设备控制仍需实际使用反馈。

- [x] **通知蓝图**：[导入指南](automations.md)和[蓝图源文件](../blueprints/automation/minij/device-notification.yaml)。
  在 HA 界面选择设备通知实体、洗衣完成/筒清洁完成/故障类型和通知动作；默认 HA 内部通知，支持配置手机渠道。
  复用官方事件及恢复基线，不创建洗涤操作，不从状态或剩余时间推断完成。
- [x] **MiniJ 自定义卡片**：[使用指南](dashboard.md)和[最小卡片 YAML](../examples/dashboard.yaml)。
  水滴形 SVG 线稿、深浅主题、滚筒动画、状态对应主按钮和参数面板；
  选择一个状态实体后自动关联同设备控件，启动/关机/筒清洁确认，HA 编辑预览禁止写入。
  通过独立 JS 资源安装，HACS 后端仓库不会自动加载。
- [x] **入口与范围**：README 提供蓝图和卡片入口，说明导入、实体对应、参数即时写入、
  云端延迟、历史消息与多设备分别配置；保留旧的独立 YAML 示例。
- [ ] **用户安装验收**：在自己的 HA 中导入蓝图、配置通知渠道和保存卡片，确认实体映射、
  手机布局及正常使用中新的官方消息交付。代码回归不算真实手机推送或多浏览器验收。
- [x] **卡片控制反馈**：区分正在发送、请求已接受和目标状态被设备上报，
  失败/不确定时提示查看机器及 App，不宣称因果、不伪造状态或自动重发。
- [ ] **排障体验**：继续区分认证、限流、云端故障和设备能力，提供可执行的恢复说明；
  诊断继续采用白名单脱敏，不暴露账号、设备或程序身份。

第一批验收标准：蓝图能通过 HA 标准输入展开和自动化校验；合成官方事件执行通知动作，
类型选择和设备隔离有效，重复读取及恢复基线不重放旧完成；卡片隔离不同设备、使用动态参数允许值，确认前上下文变化时不写。
可视化验收与真实通知另列，不为测试要求额外运行洗涤。

## 1.0：V6-XNB 完整使用体验

“完整”是新用户能独立安装、登录、监测、自动化并使用已支持的控制，遇到错误能恢复。
设备不支持或证据不足的功能清楚列明，不为凑齐 App 菜单而编造协议。

- [ ] **能力矩阵**：逐项列出已支持、未支持和证据不足；现场观察、云端回读和合成回归分列。
- [ ] **认证与恢复**：自然遇到令牌过期时验收同账号重新认证，保留实体 ID、自定义名称、区域和自动化引用；
  发现真实刷新机制后再实现续期，不假设有效期。
- [ ] **持续使用与独立安装**：收集至少 14 天正常使用的可用性/恢复记录和另一位用户按中文文档独立安装反馈；
  这是观察窗口，不证明全部会话或固件行为。
- [ ] **周期缺口**：进一步核对暂停/烘干/空闲的时间语义、故障码、取消/停止与完成的边界；
  保留未知值，不提供无证据的预计结束时间或物理离线结论。
- [ ] **多设备生命周期**：核对账号隔离、绑定/解绑、添加移除、重载、升级和用户设置保留。
- [ ] **维护质量**：按 HA 质量规范复核类型、非阻塞 I/O、配置流程、诊断、日志隐私和支持版本，
  把具体缺口拆成小 PR；不为形式上的完整添加抽象层。
- [ ] **候选发布**：针对确切候选提交核对 Linux CI、实际安装 ZIP、隐私及升级；
  合并、发布和设备验收分别记录。

## 社区、多型号与分发

- [ ] 将每个新型号作为独立支持项收集合成回归、脱敏元数据和所有者反馈；安装成功不代表控制已验证。
- [ ] 复核 HACS 默认列表申请时的实际要求并准备申请；自定义仓库当前已可用，不能提前宣称已收录。
- [ ] 区分集成页面、HACS 库和更新实体的图标来源，跟踪各渠道实际显示；本机自定义不等于上游修复。
- [ ] 维护中文型号反馈模板、已知问题和支持政策；不公开原始诊断、手机号、令牌或真实设备标识。

## 独立研究方向

预约等新控制从官方 App 的实际请求、载荷和读回入手；拿到协议前不根据名称猜测参数。
局域网/BLE/MQTT、固件更新、进入 HA Core 分别评估，不阻塞现有云端集成的可用交付。
研究不自动授权操作真实设备；取证和现场控制需遵循已约定的设备状态及操作范围。
